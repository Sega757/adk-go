## 2025-02-24 - SSRF Protection Destroys Opaque Transports
**Vulnerability:** The `clientWithSSRFProtection` wrapper silently destroyed opaque transport layers (like `oauth2.Transport` holding authentication or mTLS certs) because it used type assertions to find an underlying `*http.Transport` and fell back to cloning `http.DefaultTransport` if one wasn't directly found.
**Learning:** In Go, `http.RoundTripper` chains are largely opaque. Applying a wrapper that relies on modifying `*http.Transport`'s `DialContext` MUST be done at the very bottom of the chain. If it's applied over an opaque wrapper, the wrapper is lost.
**Prevention:** Apply low-level transport modifications (like SSRF `DialContext` overrides) to the base `http.DefaultClient` or a concrete `*http.Transport` *before* injecting it into `htransport.NewHTTPClient` or other chain-building functions. Update wrappers to return the base client unchanged if they cannot safely unwrap or clone the transport, ensuring they fail safely instead of silently stripping security headers or auth tokens.
