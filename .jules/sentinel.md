## 2026-11-06 - Replacing io.LimitReader with http.MaxBytesReader for HTTP request payload bounds
**Vulnerability:** In Go HTTP server handlers such as Agent Engine's controller, reading `req.Body` wrapped only in `io.LimitReader` quietly truncates the read payload at the limit without aborting the underlying TCP connection or rejecting the request with an HTTP 413 error. When large payloads are sent, the connection remains open for arbitrary data streaming and truncated invalid JSON is parsed or processed, which risks server resource exhaustion or denial of service.
**Learning:** `io.LimitReader` only returns `io.EOF` once its byte count reaches 0, which cannot distinguish between a normally finished stream and an oversized stream. In contrast, `http.MaxBytesReader(w, req.Body, limit)` wraps the body and sets the connection read limits, signaling a `*http.MaxBytesError` upon exceeding the limit and closing the connection if the client continues sending data.
**Prevention:** Always use `http.MaxBytesReader` for enforcing request body size limits in Go HTTP servers, inspect for `*http.MaxBytesError` with `errors.As`, and return HTTP 413 StatusRequestEntityTooLarge.
